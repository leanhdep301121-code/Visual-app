## 2. 真机要测什么（按优先级）

1. **主界面渲染正常**（练习/我的 不是白屏）。白屏只在模拟器出现（§4），真机应正常；若真机也白 → 立刻反馈，那是真 bug。
2. **实时检测（最重要）**：**自己架手机拍自己挥杆**（人占满画面、down-the-line 或 face-on）。看挥杆能否稳定检测、计数对不对、教练卡+语音出不出。
3. **光照**：故意背光站位 → 脸会不会自动提亮；"人脸偏暗"提示条在正常光线下**会不会乱弹**（实测对户外阴影脸偏敏感，重点看过敏）。
4. **动态保存（本轮重点）**：连续打一节 20+ 杆，结束 → 进历史看**是不是只留了少数几条视频**（不是每杆都存）；多打几节看手机存储有没有被撑爆。
5. **全链路 + 性能**：录→检测→教练→结束→会话报告；打一节下来**烫不烫、掉不掉电、卡不卡**（实时 YOLO+PoseTCN 真机功耗）。
6. **顺手**：我的页是否清爽；语言切 English 重开文案对不对；上传一段视频（backup 路径）出不出分析。

## 3. 已知发现（测之前先知道，省得误判）

- **检测**：YouTube 广播机位的挥杆，实时 tracker 多被拒（`0/6 mid-events，疑走过画面`）。PoseTCN 是按**用户自拍近景**训练的，转播角度识别不可靠 → **测检测请用自拍机位素材，别用 YouTube 片**。
- **光照**：大晴天户外会判"人脸偏暗"（球员低头戴帽、脸在阴影）。逆光判定本身没错，但自拍户外也会触发，留意是否过敏。
- **点测光/点对焦**：写了但没启用（点位映射方向没在真机验过），现在只开了全局自动提亮。真机可顺便验点位映射方向（同 VideoRecorder 朝向注记）。

## 4. 模拟器白屏（已定位，真机不受影响）

现象：模拟器跑久了后整屏白（连纯 `Color` 视图都不渲染），开屏图/视频画面能渲染。
根因：这套 iOS 26 beta 模拟器的 MPS/GPU 后端不支持，YOLO/基准走 `.all` 每帧抛 `E5RT...MpsGraph backend validation on incompatible OS`，持续 Metal 异常拖垮 SwiftUI 渲染上下文。
已修：模拟器上 YOLO 强制 cpuOnly、启动跳过 LatencyBench（真机路径 `.all` 不变）。
**真机用 ANE/GPU，无此问题。** 如真机仍白，才是真 bug。

## 5. 还没做（不在本 build）

- **多摄/电影/长焦特写上主流程**：仍只在 DEBUG 实验台（我的 → 拍摄实验台，或 `CAPTURELAB=1`），没并进常开的分析/录制流。原因：多摄/电影会吃满 ISP + 发热翻倍，要把 session 换成 MultiCamSession，且多摄在模拟器跑不了、只能真机验。计划：合进 CameraService，分析永不丢、能力 gate。**建议你真机测时一起验这条的热/性能可行性。**
- 用户"留这杆"的手势/语音触发（动态保存的标记钩子已就位，触发未接）。
